GCP の費用を見直すとき、「これをやれば安くなる」という定番の施策がいくつかあります。実際に検討してみると、**自分の環境では見送った方がいいもの** もいくつかありました。

やったことより、やらなかったことの方が他の人の判断材料になると思うので、その理由をまとめておきます。

**前提**：個人開発の GCP プロジェクトが5つほど。WordPress を動かす VM（e2-medium / us-central1）と、画像生成アプリの Cloud Run（GPU）が費用の大半です。

## 1. VM を e2-small にダウングレードする → 見送り

WordPress を動かしている VM は e2-medium（メモリ 4GB）です。e2-small（メモリ 2GB）にすれば、VM の料金はおよそ半分になります。

これは **過去に失敗した実績があるので見送り** ました。以前メモリ 2GB で運用していたとき、WordPress で画像をアップロードすると処理が失敗することがありました。画像のリサイズやサムネイル生成でメモリを使うためです。

数百円を節約するために、記事を書くときに毎回ストレスを感じるのは割に合いません。メモリが多めで安いマシンタイプが新しく出たら、そのときに考え直すことにしました。

## 2. 東京・大阪リージョンに移す → 見送り

利用者は日本にいるので、VM を東京（asia-northeast1）や大阪に移せば応答も速くなりそうです。

ただ、**Cloud Billing の SKU の単価を比べると、東京は us-central1 より約28%高い** ことが分かりました。同じ構成でも、場所を変えるだけで3割近く高くなります。

このサイトは手前に Cloudflare があり、ページはほとんど Cloudflare のキャッシュから返されます。VM の場所が利用者から遠くても体感への影響は小さいので、料金の安い us-central1 のままにしました。

なお、us-central1・us-west1・us-east1 の e2-micro には常時無料枠があります。小さいサービスなら、米国リージョンの方がさらに有利です。

## 3. モデル置き場のバケットを Nearline にする → 見送り

画像生成モデルを置いている Cloud Storage のバケットは、Standard クラスです。Nearline にすれば、保存料金は半分くらいになります。

ただし Nearline は、**データを読み出すたびに取得料金がかかり**、最低保存期間（30日）もあります。月1回も読まないようなバックアップ向けのクラスです。

このバケットのモデルは、GPU での推論に使うために繰り返し読み出します。読み出しが頻繁なので、Nearline にすると取得料金で逆に高くなります。**頻繁に読むデータは Standard のままが正解** でした。

## 4. Standard ティアへの切り替え → いったん保留（後で実施）

VM の外向き通信を Premium ティアから Standard ティアに切り替えると、月200GiBまでの無料枠が使えます。

最初の見直しでは、**外部 IP アドレスが変わって DNS の書き換えが必要になる** ことから保留にしました。その後、外向き通信の内訳を詳しく調べて、削減額（月 ¥600〜700ほど）がはっきりしたので、2回目の見直しで実施しています。

ところが、切り替えたあとも Cloudflare 向けの通信は Carrier Peering として課金され続け、**削減効果はありませんでした**（2026-10-28 追記）。結果的には、最初の判断どおり保留でよかったことになります。

詳しくは [GCP の請求で Networking は ¥0 なのに、VM の通信料がかかっていた](/articles/gcp-vm-egress-404-gzip/) に書きました。

## 確認して「問題なし」だったもの

「他にも削れるところはないか」と一通り確認して、費用が発生していなかった項目です。チェックリストとしてどうぞ。

| 項目 | 確認結果 |
|---|---|
| 静的外部 IP | どのプロジェクトでも予約なし（未使用の静的 IP は課金される） |
| Cloud SQL / Memorystore | 未使用（API 自体が無効） |
| Cloud NAT / VPN / Interconnect | 未使用 |
| Cloud Scheduler | 未使用 |
| Cloud Logging の取り込み量 | 全プロジェクト合計で月63MB程度。無料枠（50GiB）の0.1%で課金なし |
| 予算アラート | 全体・プロジェクト別ともに設定済み |
| Cloudflare のキャッシュ | Smart Tiered Cache が有効、画像は1年キャッシュでヒットしている |

費用が発生しているサービスを見るだけでなく、**「よく課金の原因になるもの」を一通り潰しておく** と安心できます。特に、使わなくなった静的 IP や停止中の VM のディスクは、忘れた頃に請求が来がちです。

## 見送るときに考えたこと

見送った判断を振り返ると、基準は次の2つでした。

- **過去にトラブルがあった設定には戻さない**：数百円の節約より、運用中にまたトラブルが起きるリスクの方が高くつく。
- **単価ではなく使い方で比べる**：Nearline も東京リージョンも、カタログ上の単価だけを見ると判断を誤る。読み出し頻度や、Cloudflare を挟んでいるかどうかで結論が変わる。

GCP の費用見直し全体の流れは、[Claude Code に GCP の課金を棚卸しさせたら、月1万円が半分になった](/articles/claude-code-gcp-cost-review/) にまとめています。
